# 하루이음 스터디 통합 기획안 1.0

> 상태 표기: `[확정]` 결정된 사항 / `[제안]` 검토 중인 제안 / `[미정]` 추가 결정이 필요한 사항 / `[보류]` 의도적으로 결정을 미룬 사항 / `[법률]` 법률 검토가 필요한 사항
>
> `[법률]` 표시는 해당 항목의 구체 문구·요건을 법률 검토 후 정한다는 뜻이며, 그 항목이 속한 절의 확정 상태를 낮추지 않음.
>
> 범위: 하루이음과 물음샘의 통합 이후 제품 구조, 기능, 권한, 기술 및 운영 원칙. 전환기 임시 운영과 구체적인 개발 일정은 별도 관리함.
>
> 문서 상태: 제품 기획 기준안 1.0. `[전체 확정]`은 제품 정책 확정을, `[대부분 확정]`은 일부 세부 사항이 남아 있음을 의미함. 실제 구현 및 외부 출시 준비 완료를 뜻하지 않음.

- 물음샘 홈에서 학습 기능을 바로 선택할 수 있도록 하며, 별도의 불필요한 학습 시작 관문을 두지 않음.
- 게임화는 물음샘의 학습 동기부여와 나의 누적 현황을 중심으로 제공하고, 오늘·다음에는 과도하게 노출하지 않음.
- 이야기를 이용하지 않아도 학습할 수 있어야 하며 DM·쪽지는 제공하지 않음.

### 2-1. 내비게이션

- **모바일 하단 탭바에는 정확히 다섯 개의 탭 아이콘만 표시하는 것을 기본값으로 함.** 선택 탭에도 이름을 표시하지 않음. 이용자는 설정에서 탭 라벨 표시를 켤 수 있음.
- 태블릿·데스크톱은 아이콘과 이름을 함께 표시함. 넓은 화면에서 좌측 내비게이션을 우선 검토하며 가용 화면 너비에 따라 전환함.
- 화면 최상단에는 고유 제목을 크게 표시함. 탭의 위치와 터치 영역은 선택 여부에 따라 변하지 않으며 선택 상태는 명확하게 구별함.
- 모든 탭에 접근성 이름과 선택 상태를 제공함. 아이콘 인지도 및 반응형 배치는 사용성 검증 대상으로 관리함.
- 물음샘 홈은 일반 탐색 화면으로 구성하며, 실제 문제 풀이·필기·답안·채점에서는 전역 내비게이션을 숨기거나 접는 집중 학습 모드를 사용함.

### 2-2. 비로그인 이용

- 비로그인 사용자는 물음샘만 이용할 수 있음. 다른 탭의 회원 전용 기능에는 접근할 수 없음.
- 비로그인 상태에서 생성한 기록의 저장·이전 정책은 6-3을 따름.

## 3. 계정 유형·대상 설정·일정 `[대부분 확정]`

### 3-1. 계정 유형과 가입 시 선택

가입 시 계정 유형과 하위 선택지를 고름.

| 계정 유형 | 선택지 | 성격 |
|---|---|---|
| 학생 | 고1 / 고2 / 고3 / N수생 / 재학습 | 학습·일정·이야기를 쓰는 일반 계정 (2장의 5탭) |
| 교사 | 학교 / 학원 / 스터디그룹 중 1택 | **그룹 관리용 계정.** 학습 기능이 아니라 별도 **관리형 UI**를 제공 |

- 교사 계정은 교사 자격을 인증하는 제도가 아님. 그룹 관리 기능을 쓰기 위한 계정 유형임. 계정 유형·그룹 내 역할·실제 운영 주체 확인은 구별함. 개설 권한은 4-4를 따름.
- **만 14세 이상 원칙은 계정 자체에 적용되며 계정 유형과 무관하게 항상 적용함.**
- 학습 단계 및 학교 정보는 자기 신고이며 실제 연령이나 소속을 인증하는 정보가 아님. 만 14세 이상 확인 및 약관·개인정보 관련 동의 기록은 별도로 관리함.
- 기준 연도와 학년을 저장하여 학년 변경 및 졸업 전환을 안내하는 방식.
- 학습 단계의 공개 프로필 노출 여부는 기본 비공개.
- 교사 계정의 관리형 UI 상세 구성은 별도 문서에서 정함. 기존 테스터는 로그인 후 첫 계정 설정을 안내한다. 최초 유형 설정은 차감하지 않는다. 유형과 하위 유형, 학습 단계, 학교·학년·반은 최근 90일에 총 세 번 변경할 수 있다. 학교·학년·반을 한 번에 저장하면 한 번으로 센다. 첫 학교 설정은 한 번으로 센다. 그룹을 소유한 계정의 학생·교사 유형 전환은 기본적으로 막으며 장기 처리 방식은 `[미정]`이다.

### 3-2. 학교·학원·개인 일정

학교 연결은 선택 기능이며 학원·개인 시간표와 병행할 수 있음.

| 출처 | 제공 정보 | 원본 관리 주체 |
|---|---|---|
| 학교(NEIS) | 시간표·급식·학사일정 | 외부 연동 원본 |
| 학원·기숙학원 그룹 | 배포된 시간표·일정 | 권한 있는 그룹 운영자, 구성원은 읽기 전용 구독 |
| 개인 | 직접 작성한 시간표·일정·모의고사 D-Day·학습 목표 | 이용자 본인 |

- 학교·학년·반 정보는 학사정보 연동 및 내 학급 그룹 탐색에 사용함. 해당 정보를 설정해도 그룹 가입이나 그룹 내부 정보 접근 권한은 자동으로 생기지 않음.
- 학교·학원·개인 일정은 **원본과 수정 권한을 출처별로 분리하고 화면에서 하나의 시간축으로 통합 표시**함. 한 출처의 갱신·삭제·구독 해제가 다른 출처의 원본에 영향을 주지 않도록 함.
- 일정이 겹치면 임의로 삭제하거나 우선순위를 확정하지 않고 같은 시간 구간에 병렬로 표시하며 충돌을 알림.
- 개인별 숨김·예외 설정, 중복 판별 기준 및 충돌 알림의 상세 UX는 **별도 문서에서 명시함.**

## 4. 그룹 시스템

### 4-1. 유형과 권한 `[확정]`

그룹 내부의 소통과 데이터 공유는 가입한 구성원 사이에서만 이루어지며, 전체 공개 광장과 구별함. 서비스가 유형별 권한 상한을 정하고 그룹장은 그 범위 안에서 운영 정책을 설정함.

- **비활성**: 기능이 비활성화되어 있음
- **1:1**: 그룹장과 해당 구성원 사이에서만 데이터에 접근할 수 있는 범위. 다른 구성원에게는 공개하지 않으며 사적인 메시지 기능을 뜻하지 않음.
- **활성**: 구성원 전체를 대상으로 활성화되어 있음

| 기능 | 학급 그룹 | 학원 그룹 | 스터디 그룹 |
|---|---|---|---|
| 성격 | 구성원 간 협력 중심 | 상대적으로 중앙 관리형 | 자율 학습·협력 중심 |
| 일정·시간표 배포 | **학교 자동 연동으로 대체** | 그룹장 설정(기본 활성) | 그룹장 설정(기본 비활성) |
| 그룹 이야기 | 그룹장 설정(기본 활성) | 그룹장 설정(기본 1:1) | 그룹장 설정(기본 활성) |
| 그룹장 기본 권한 | 가입 승인, 게시물 관리 | 학급 권한 + 일정 배포, 1:1 관리 | 학급 권한 + 그룹장 설정 |
| 구성원 총 공부 시간 | [보류] | [보류] | [보류] |
| 개인 상세 통계 | **허용하지 않음** | 그룹장 설정(기본 1:1, 상한 1:1) | 그룹장 설정(기본 비활성, 상한 1:1) |

- 학급 그룹의 공부 시간 공유는 개인의 총합 공부 시간 정도로 제한함. **공부 시간 공유 기능 자체는 확정**이며, 아래 세부 사항만 `[보류]`임.
  - `[보류]` 구체적 측정 방식·집계 단위·공개 대상·신뢰성은 물음샘 기술 부분 완성 후 결정.
- 기본값과 권한 상한은 구별함. 개인 상세 통계는 최대 1:1로 제한하고 구성원 전체에 공개하지 않음. 학급 그룹에서는 그룹장 전용 상세 통계 열람 자체를 금지함. 다른 기능의 설정 가능 단계와 세부 권한은 별도 그룹 권한 명세에서 정함.
- 학원 그룹의 통계 항목은 참여 여부·학습 시간·풀이 수·정답률 등을 후보로 하여 운영자 조사 및 법률 검토 후 결정 `[법률]`.
- 오답 내용, 세부 학습 활동 기록, 개인 일정 상세, 필기 원본, 상세 접속 기록은 그룹 공유 상한에서 제외.
- 작성자는 자신의 게시물을 삭제할 수 있고 그룹장은 숨김 권한을 갖는 방식.

### 4-2. 공유 정책과 확인 `[전체 확정]`

공유 항목을 구성원별로 선택하는 개별 승인 설정은 도입하지 않음. 그룹 정책 전체에 대한 **단일 확인**을 사용함.

| 상황 | 적용 규칙 |
|---|---|
| 최초 가입 | 현재 공유 정책을 표시하고 최종 확인 후 가입 |
| 권한 축소 | 즉시 적용 |
| 권한 확대 | 변경 내용을 표시하고 해당 구성원이 확인한 뒤에만 확대 적용 |
| 확대 확인 보류·거부 | 그룹에 계속 남을 수 있음. 새 확대 항목은 공개하지 않으며 축소 사항을 제외한 기존 유효 공유 범위 유지 |
| 지나치게 강한 공유 정책 | 가입·확대 시 경고 표시 |

- 확인 화면에는 공유 대상·항목·기간 및 변경 내용을 명확히 표시함.
- 그룹장에게 확인 완료·보류 상태를 직접 보여주지 않으나, 개인 통계를 열면 보류 중인 그룹원의 범위가 확장 이전처럼 표시되는 방식. 확인 여부에 따라 허용되지 않은 신규 데이터를 열람할 수는 없다는 원칙에 의함.
- 탈퇴 시 그룹 정보 접근과 향후 데이터 공유를 중단함. 확인 철회, 이전 공유 자료 및 보존 이력의 구체 처리와 학원 그룹에서의 동의 요건은 `[법률]`. 강한 공유 정책의 경고 기준은 별도 운영·권한 명세에서 정함.

### 4-3. 학급 그룹 탐색·가입 `[대부분 확정]`

- 학급 그룹의 식별 정보는 **학년도 + 학교 + 학년 + 반 + 고유 식별자**로 구성함. 매년 새 학년도 그룹을 만들며 같은 학급에 여러 그룹이 존재할 수 있음.
- 학교·학년·반을 설정한 이용자는 자신이 설정한 학교·학년·반이 **완전히 일치하는** 학급 그룹(이전 연도 포함)만 탐색할 수 있음. 초대 코드 입력 또는 그룹장 승인 신청으로 가입함.
- 그룹 이름·설명에는 그룹장 본인을 포함하여 개인정보를 명시하지 않도록 약관으로 규정함.

| 가입 전 표시 | 가입 전 비표시 |
|---|---|
| 학교·학년도·학년·반, 그룹 이름, 고유 식별자, 공개용 설명, **구성원 수 구간** | 구성원 명단, 그룹장 이름·프로필, 그룹 내부 게시물·개인 통계, 구성원별 공부 시간 |

- 구성원 수는 가입 전 구간으로, 가입 후 정확한 수로 표시함 `[확정]`. 인원수는 그룹의 규모를 가늠하는 단서이며 소속이나 공식성을 인증하지 않음.
- 가입 전 표기 단계: **1, 2+, 5+, 10+, 20+, 50+, 100+, 200+, 500+, 1k+**. 실제 인원수 이하인 가장 큰 단계로 표시함(4명 → `2+`, 27명 → `20+`, 1,350명 → `1k+`). 이전 연도 그룹에도 동일하게 적용함.
- 검색 시 정확한 구성원 수나 내부 정보가 반환되지 않도록 함. 학교 설정 변경·반복 조회의 남용 방지와 인원 집계 대상은 별도 권한·백엔드 명세에서 정함.

### 4-4. 그룹 개설 및 그룹장 이양 `[대부분 확정]`

| 계정 유형 | 학급 그룹 | 학원 그룹 | 스터디 그룹 |
|---|---|---|---|
| 학생 | 가능 | 불가 | 가능 |
| 교사(학교) | 가능 | 불가 | 불가 |
| 교사(학원) | 불가 | 가능 | 불가 |
| 교사(스터디그룹) | 불가 | 불가 | 가능 |

- 그룹의 최초 개설자가 그룹장임. 임시 그룹장 개념은 두지 않음. 계정 유형과 그룹장 역할은 별개이며 중복 그룹은 고유 식별자로 구별함.
- 학원 그룹은 초대 코드 및 직접 신청으로 관리함. 교사(학원) 계정만 학원 그룹을 개설할 수 있으며 강한 관리 권한은 운영 주체 확인 후 부여함. 확인 방법과 승인 기준은 별도 운영 명세에서 정함.
- 그룹장 이양은 **현 그룹장이 지정한 적격 구성원에게 즉시 승계**하는 방식으로 처리함. 대상자의 별도 수락은 요구하지 않음 `[확정]`. 그룹 유형별 관리 자격 및 운영 주체 확인 요건을 우회할 수 없음. 기존 그룹장의 전용 권한은 종료됨.
- 이양 통지·이력 기록 및 원자적인 권한 교체를 권장함 `[제안]`.
- 그룹장 변경 시 종전 확인의 효력은 종료된다. 구성원이 이양 안내를 확인한 뒤에만 허용 범위의 상세 통계가 새 그룹장에게 공개된다. 확인을 미룬 구성원은 그룹에 남을 수 있다. 이양·확인 시각을 기록하고 확인 상태는 그룹장 화면에 표시하지 않는다. 그룹장 탈퇴·계정 삭제·장기 부재 시 그룹 처리 방식은 `[미정]`·`[법률]`. 자동 승계 없이 이양 또는 그룹 잠금·보관으로 처리하는 방안을 권장함 `[제안]`. 계정 삭제를 이양 완료의 강제 조건으로 제한하지 않도록 검토함.
- 학교 전체 그룹 유형의 추가는 `[보류]`. 현재 학급·학원·스터디의 세 가지 유형을 유지함.

### 4-5. 그룹 관리 및 신고 `[확정]`

- 운영자는 광장을 관리하고 그룹장은 그룹 내부의 일상적인 게시물 관리 및 운영을 담당함.
- 이용자는 그룹 자체뿐 아니라 그룹 내부의 안전 문제·괴롭힘·개인정보 침해·그룹장 권한 남용 등을 운영자에게 직접 신고할 수 있음. 그룹장이 신고 대상인 경우에도 가능함.
- 운영자는 신고 대응에 필요한 최소한의 그룹 콘텐츠와 관련 정보를 열람할 수 있도록 함. 열람 사유·이력, 그룹 제한·제재 절차, 관계 기관에 대한 법령상 제공 요건과 구체적인 약관 문구는 별도 운영 정책 및 `[법률]` 검토에서 정함.

## 5. 이야기

### 5-1. 공간과 공개 범위 `[전체 확정]`

| 공간 | 접근 기준 |
|---|---|
| 그룹 | 실제 가입·승인된 학급·학원·스터디 그룹의 구성원. 그룹 정책에 따라 전체 또는 1:1 범위로 접근 |
| 광장 | 그룹 가입과 관계없는 회원의 전체 공개 소통 공간 |

- 이야기 화면 안에서 그룹과 광장을 따로 탐색하고 따로 글을 작성함.
- 글·댓글·리포스트·반응·프로필 및 글 공유를 제공함. 게시물의 공개 범위는 현재 공간과 유효 그룹 정책에 따르며 글 작성 시 명시함. 1:1은 관리 목적의 제한된 접근 범위이며 사적인 메시지 기능은 제공하지 않음. 1:1 이야기의 작성·댓글 권한 등 구체적인 기능 범위는 별도 명세에서 정함.
- 그룹 게시물과 광장 게시물은 서로 리포스트·재공유할 수 없음. 링크·첨부·미리보기 또한 기존 접근 권한을 따라야 함. 작성자가 별도의 전체 공개 글 또는 그룹 게시물을 새로 작성하는 경우는 구분함.
- 게시물·공개 프로필에는 닉네임과 핸들을 사용함. 학교·반·번호를 공개 프로필 필드로 제공하거나 자동 노출하지 않으며, 본문 등 이용자가 직접 입력하는 개인정보는 운영 정책으로 제한함.
- 물음샘의 문제·풀이를 이야기로 공유하고 공유된 학습 콘텐츠를 물음샘에서 열 수 있음. 원래 게시물의 공개 범위를 유지함.
- 그룹 이야기를 먼저 공개하고 광장은 그 이후 공개함. 각각 보호 장치와 운영 준비, 9-1의 출시 기준을 충족해야 함.

### 5-2. 외부 연락·링크 정책 `[확정]`

- 광장과 그룹 모두에서 공개 학습 자료, 학교·학원 등 기관의 공식 공지 및 안전 정책에 부합하는 일반 웹 링크는 허용함. 외부 이동 시 안내 또는 경고를 제공함.
- 개인 연락처·개인 SNS 계정의 공개는 제한하고, 개인정보 요구·수집·공개 강요, 사적 외부 연락·채팅방·만남 유도, 사기·유해 링크·무단 광고 및 금전 거래는 금지함. 교사 계정에도 동일한 원칙을 적용함.
- 성인과 미성년자가 함께 이용하는 공간의 보호 조치를 우선하며 세부 탐지·제한·신고 기준은 별도 운영 정책에서 정함.

## 6. 계정·학습 기록·데이터 `[대부분 확정]`

### 6-1. 공통 계정

- 기존 물음샘의 계정·Firebase Auth UID를 통합 서비스의 공통 사용자 식별자로 사용함. 하나의 프로필·닉네임·핸들·계정 설정을 제공함.
- 기존 계정 및 계정에 저장된 학습 기록을 보존하고 학교·일정·그룹 데이터와 연동함.
- 학교·학급·시간표·개인 일정 및 개인 학습 기록은 기본 비공개로 관리함. 그룹 공유는 4장의 정책에 따르며 반·번호는 공개 프로필에 표시하지 않음.

### 6-2. 기능 간 연계

| 연결 | 기능 |
|---|---|
| 오늘 → 필기 | 현재 수업과 관련된 학습 실행 |
| 다음 → 물음샘 | 시험 범위와 계획에 따른 학습 실행 |
| 물음샘 → 나 | 학습 결과·진행 현황·통계 반영 |
| 물음샘 ↔ 이야기 | 문제·풀이 공유 및 공유된 콘텐츠에서 학습 진입 |

### 6-3. 학습 데이터

- 문제공방·암기마스터의 문제 생성, 풀이·채점·복습 엔진을 독립 모듈로 유지하고 재사용함.
- 비로그인 학습과 기존 브라우저 로컬 저장을 유지하고, 필기·진행·복습 기록의 내보내기·가져오기 및 복구를 지원함. 이 기능은 **기기·브라우저의 로컬 기록을 백업·복구하는 용도**이며, 계정 기록으로 반영하지 않음.
- **비로그인 상태에서 쌓은 로컬 기록은 로그인 후 계정에 가져오지 않음** `[확정]`. 이유는 다음과 같음.
  - 로컬 기록은 브라우저에 저장되어 콘솔 등으로 점수·시간 등을 조작할 수 있고, 서버가 신뢰성을 확인할 수 없음.
  - 가져온 기록을 공인 점수에서 제외하거나 부정으로 처리하면 정당한 이용자가 오해할 수 있고 안내·분쟁 처리가 복잡해짐.
  - 가져오기를 반복할 수 있으면 조작한 기록을 담은 계정을 계속 새로 만들 수 있음.
- 로그인 세션 종료 시 Cloudflare Workers에서 획득 점수·XP를 한 번 대조한다. 일치하면 그 세션의 합계만 누적한다. 불일치 안내와 이의 제기를 제공하고 통신·서버 오류에는 재시도를 제공한다. 랭킹은 닫혀 있다. 계산식과 적용 범위는 [세션 검증 설계](SESSION_VERIFICATION.md)를 참고한다.
- `[미정]` 실제 정답·학습 행위에 대한 독립 검증과 공개 랭킹 기준은 추가 설계가 필요하다.
- `[제안]` 가입·로그인 화면에서 "로그인하기 전에 쌓은 기록은 계정으로 옮겨지지 않는다"는 점을 안내함.
- 자동 동기화 범위, 백업·복구의 상세 명세는 따로 정함.

## 7. 기술 구조 `[대부분 확정]`

| 항목 | 방향 |
|---|---|
| 앱 형태 | PWA(차후 스토어에서의 웹앱으로 확장 가능) |
| 개발 기술 | JavaScript |
| 백엔드 | **현재 물음샘 Firebase 프로젝트**에 하루이음 기능을 통합 |
| 인증 | Firebase Authentication |
| DB | Cloud Firestore |
| 접근 통제 | Firestore Security Rules 우선 |
| 별도 서버 처리 | Cloudflare Workers 연동 |
| 운영 원칙 | 저비용 운영, 기존 기술 자산 보존, 논리적 모듈 분리 |

- 하루이음에는 기존 DB·백엔드 기반이 없으므로 물음샘의 Firebase 프로젝트를 공통 기반으로 사용함. 새 프로젝트를 전제로 한 인증·DB 이전은 하지 않음.
- 공통 데이터 계약과 사용자 식별자를 정의하고 학습 엔진·일정·커뮤니티 등 기능별 모듈의 독립성을 유지함. 제품 통합과 저장소의 물리적 통합은 별개임.
- Security Rules를 이용해 소유권, 그룹 가입 상태, 역할별 권한 및 구성원별 유효 공유 정책을 검증함. UI에서 숨기는 것만으로 접근 제한을 구현했다고 간주하지 않음.
- 학습 종료 시 포인트·XP 교차 검증, 중복 보상 방지, 필요한 권한 이력, NEIS API 키 보호·호출량 관리 등 신뢰 가능한 서버 처리는 Workers로 수행함. 개별 문제 전수 서버 채점은 하지 않음(6-3 참조). Rules만으로 신뢰성을 확보할 수 없는 공인 기능은 검증 없는 상태로 제공하지 않음.
- 기존 Firestore Security Rules 테스트와 Playwright E2E를 보존하고 통합 기능의 권한·무결성·회귀 테스트를 보강함.
- 화면별 Firestore 문서 읽기량과 구독량을 측정·추정해 데이터 구조와 비용을 검토함. 불필요한 실시간 구독을 최소화함.
- `[미정]` 컬렉션 구조·인덱스·Rules 상세 구현.
- `[미정]` Workers의 무료 한도, Firebase ID 토큰 검증 방식, 호출량 증가 시 비용은 공식 문서로 확인한 뒤 설계에 반영함.
- Firebase Cloud Functions·Blaze 전환 및 Supabase 이전은 `[보류]`.

## 8. 공통 디자인 시스템 `[대부분 확정]`

- 기존 물음샘 디자인 시스템 v4를 기반으로 하루이음 Figma 원본의 구조를 적용하여 **Harueum Design System**을 구성함.

- 일반 탐색은 엄지존 우선, 문제 풀이·필기는 필기존 우선으로 설계함. 물음샘의 버튼·토글·슬라이더·수식·필기 규칙과 하루이음 Figma의 고대비·정보 밀도·위계·한 손 조작 원칙을 반영함.
- 정보 요소와 조작 요소의 표현을 구별하고 기능·정보가 불필요하게 반복되지 않게 구성함. 내비게이션은 2장의 규칙을 따름.
- 하루이음의 하늘색과 물음샘의 청록색은 전부 청색 계열이므로 단일 색으로 일치화함. 최종 색상값과 대비 규칙(텍스트·버튼에 쓰는 색의 대비 포함)은 디자인 시스템에서 검토함 `[미정]`.

## 9. 운영·안전·이용약관

### 9-1. 운영 원칙 및 공개 조건 `[확정]`

- 신고·숨김·차단 기능 및 통합 이용약관·개인정보 처리방침은 통합 개발 범위에 포함함.
- 외부 이용자 공개 전 신고 처리 기능·절차·연락 창구, 약관·처리방침 및 가입 시 확인·동의 기록을 갖추는 출시 기준.
- 그룹 이야기·광장의 공개 권한에 따라 게시물 관리 및 신고·제재 정책을 적용함. 청소년의 개인정보 보호와 안전을 고려함.

### 9-2. 약관·개인정보 처리방침의 범위 `[확정]`

- 서비스 명칭·운영 주체·제공 기능, 기존 계정과 기록, 비회원 학습 범위.
- 계정 유형(학생·교사), 비로그인 로컬 기록이 계정으로 이전되지 않는다는 점.
- 학교·학급·개인 일정 정보의 수집 목적과 보호, 공개 프로필·핸들·학습 기록의 공개 범위.
- 그룹 가입·탈퇴, 그룹장 권한 상한, 권한 확대 확인 및 데이터 공유·보존·철회.
- 그룹 이름·설명의 개인정보 금지, 신고된 그룹 내용의 운영자 열람 및 관계 기관 제공.
- 게시물의 권리와 공개 범위, 재공유, 신고·숨김·차단·제재·탈퇴, 개정 및 동의 절차.

### 9-3. 법률 검토 `[법률]`

- 가입 연령, 미성년자의 법정대리인 동의 요건 및 성인·미성년자 혼재 공간의 보호 의무.
- 그룹장과 개인 운영자의 개인정보 처리 관계 및 책임, 학급 그룹장이 학생인 경우의 책임.
- 그룹 정책의 단일 확인과 통계 공유에 필요한 법적 동의 요건, 학원 그룹에서의 자발성, 동의 철회 및 탈퇴 후 자료 처리.
- 신고된 그룹 내용의 운영자 열람 요건·범위와 관계 기관 제공의 근거 및 절차. 그룹장 이양으로 열람자가 변경될 때 기존 공유 확인의 효력.
- 개인 운영자의 공개 정보·연락처·보호 책임 및 학원 그룹 유료화 시 필요한 사업자 관련 요건.

구체적인 법적 문구와 판단은 별도 검토 후 확정함.

## 10. 조사 계획 `[전체 확정]`

기존 고등학생 대상 설문만으로는 N수생·재학습자·학원 운영자의 수요를 판단할 수 없으므로 추가 조사를 실시함.

| 대상 | 조사 내용 |
|---|---|
| N수생·재학습자 | 시간표·모의고사·자습 계획 관리 방식, 학원 공지 수신 경로, 그룹 공유를 원하는 정보와 원하지 않는 정보, 통계 공유 조건에 대한 수용성 |
| 학원·기숙학원 운영자 | 일정·출결 전달 방식, 필요한 통계와 권한 상한, 상세 오답·수업 기록 없이도 사용할 의향, 개인정보 동의 절차, 유료 기능 수요 |

미성년자 조사에는 필요한 보호자 동의 및 기관 기준을 준수함. 구체적인 조사 방법은 별도 계획으로 관리함.

## 11. 후속 설계 및 검토

1.0은 제품의 상위 정책을 확정한 기준 문서이며, 다음 세부 사항은 해당 문서에서 결정함. 실제 공개 전에는 9장의 출시 조건과 법률 검토를 충족해야 함.

| 별도 문서·검토 | 범위 |
|---|---|
| 그룹 및 권한 명세 | 계정 유형 변경, 그룹장 부재·탈퇴·계정 삭제, 이양 시 공유 확인 효력, 기능별 설정 가능 단계, 1:1 콘텐츠 권한, 구성원 수 집계·검색 남용 방지, 강한 공유 정책 경고 기준 |
| 화면·UX 명세 | 학생·교사 UI, 일정 숨김·예외·중복·충돌 표시, 이야기 공간 및 작성 UX, 비로그인 안내 |
| 물음샘 학습 명세 | 학습 종료 포인트·XP 교차 검증, 검증 근거와 보장 범위, 학습 기록 동기화·백업·복구 |
| 백엔드 아키텍처 | Firestore 컬렉션·인덱스·Rules, Workers 토큰 검증·한도·비용, 세션 중복 제출 및 권한 변경 처리 |
| 디자인 시스템 | 단일 브랜드 색상값·대비, 공통 토큰·컴포넌트·반응형 레이아웃 |
| 운영 및 안전 정책 | 신고·차단·제재·링크·개인정보 보호, 그룹 운영 주체 확인 기준, 이용약관·개인정보 처리방침 및 9장의 `[법률]` 검토 |
| 조사 계획 | N수생·재학습자·학원 운영자 조사 및 통계 항목 검토 |

**`[보류]` 유지:** 공부 시간의 구체적 측정·집계·공개 대상·신뢰성(물음샘 기술 완성 후), 학교 전체 그룹 유형 추가, Firebase Cloud Functions·Blaze 전환 및 Supabase 이전.

## 부록. v0.6 → 1.0 변경 기록

1. 학생 및 교사 계정별 그룹 개설 권한을 확정하고 학원 그룹의 강한 관리 권한에는 운영 주체 확인을 요구함.
2. 1:1을 데이터 접근 범위로 정의하고 사적 메시지 기능과 구분함. 상세 통계의 상한을 최대 1:1로 제한함.
3. 그룹장 이양은 대상자 수락 없는 즉시 승계로 확정함. 탈퇴·부재·삭제 처리 및 이양 시 공유 효력은 별도 검토로 구분함.
4. 가입 전 구성원 수는 지정된 구간(1~1k+)으로, 가입 후에는 정확한 수로 표시함. C안을 유지함.
5. 그룹 내 안전 문제·권한 남용 등에 대한 운영자 직접 신고를 허용하고, 신고 열람과 법적 제공 절차를 별도 검토로 정리함.
6. 외부 연락·링크 정책을 확정하고 그룹 이야기 및 광장의 공개 조건을 정리함.
7. 학습 종료 시 포인트·XP 교차 검증 후 공인 기록을 갱신하는 방식으로 확정함. 개별 문제 전수 서버 검증은 제외하고 검증의 근거·한계를 기술 명세로 분리함.
8. 학교 전체 그룹 추가를 보류하고 학급·학원·스터디 세 유형을 유지함.
9. 외부 공개 조건을 필수 확인 항목으로 정리하고, 세부 설계와 법률 검토를 후속 문서로 분리함.
