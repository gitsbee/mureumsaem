# 학습 세션 검증 설계

- 로그인 사용자가 풀이 화면을 나가거나 완료 화면에 도착하면 한 번 제출한다. 클라이언트는 화면에서 얻은 결과로 점수와 XP를 계산하고, Worker는 토큰 소유자의 Firestore 풀이 문서를 찾아 건수와 결과로 다시 계산한다. 정답·힌트 정답은 각각 3점·1점, XP는 유효 풀이당 1에 점수를 더한다. 이 값은 초기 가정이며 이미 기록된 세션에는 계산을 다시 적용하지 않는다.
- 브라우저가 만든 UUID를 세션 ID로 쓴다. Worker의 서비스 계정만 결과를 생성한다. 성공 시 세션과 풀이 ID의 사용 기록을 생성하고 총점과 XP를 같은 Firestore 커밋에서 증가시킨다. 같은 세션의 재시도는 저장된 결과를 반환한다. 다른 세션에 사용된 풀이 ID를 재사용할 경우 확인 실패로 처리한다.
- Firebase ID 토큰은 Firebase의 `accounts:lookup`에서 프로젝트 웹 API 키로 확인한다. 확인된 UID를 경로에 사용한다. 서버 쓰기는 Firestore 접근을 부여한 서비스 계정의 OAuth 토큰으로 수행한다.
- 서버와 클라이언트의 계산값이 다르면 불일치를 기록한다. 누락·통신·인증·서버 오류는 확인 실패로 처리하고 같은 ID로 재시도한다. 브라우저가 저장소 접근을 허용하면 미확인 요청을 그 브라우저에 남긴다. 잘못된 세션의 불일치 기록이 다른 세션의 점수나 판정에 영향을 주지 않는다. 이의 제기는 불일치 세션당 한 건, 계정당 UTC 하루 세 건으로 제한한다.
- 이 검증은 계정에 저장된 풀이 기록과 획득값의 일관성을 검사한다. 기존 풀이 결과는 브라우저 채점을 기반으로 하므로 실제 정답이나 학습 행위를 독립적으로 입증하지 않는다. 랭킹은 그 신뢰 범위와 운영 기준이 확정될 때까지 닫는다. 로컬 미로그인 기록과 백업은 제출하지 않는다.
- Cloudflare Workers Free의 공개 한도는 하루 100,000 요청, 호출당 외부 요청 50회다. 세션당 풀이 최대 400건은 Firestore batchGet 한 요청으로 읽는다. 검증은 Firebase 조회와 Firestore 읽기·커밋을 포함하고, Firestore 읽기량은 세션 풀이 수에 비례한다. 출시 전 실제 한도와 사용량을 다시 확인한다. [Workers 한도](https://developers.cloudflare.com/workers/platform/limits/)
